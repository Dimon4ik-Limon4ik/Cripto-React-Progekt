## Порты: 3000 и 5173 были заняты — что сделано

Перед запуском проверено `netstat -ano`:

| Порт | Состояние | Что это |
| --- | --- | --- |
| 3000 | **занят** (PID 16912, `node.exe`) | ваш dev-бэкенд |
| 5173 | **занят** (PID 6356, `node.exe`) | ваш dev-фронтенд (Vite) |
| 3104, 5174 | свободны | использованы тестами |

**Ваши процессы не останавливались** (это состояние вне `test/`, и они могут работать с рабочей БД). Вместо этого тесты поднимают **свои** экземпляры:

| Сервис | Адрес | Запуск |
| --- | --- | --- |
| Тестовый бэкенд | `http://127.0.0.1:3104` | `node --import test/api/support/fetch-stub.mjs server.js`, `NODE_ENV=test`, `DATABASE_URL_TEST` — только в среде процесса |
| Тестовый фронтенд | `http://127.0.0.1:5174` | `vite --config test/ui/vite.e2e.config.mjs` (свой конфиг: `cacheDir` внутри `test/tmp`) |

`test/ui/support/global-setup.mjs` перед стартом проверяет, что 3104 и 5174 **свободны**, и отказывается работать, если нет. Порты 3000/5173/5432 запрещены константами в `test/ui/support/env.mjs` — случайно занять их тесты не могут.

### Как браузер попадает на тестовый бэкенд

В `src/Services/*.js` адрес API зашит как `http://localhost:3000`, то есть вашему dev-серверу. Чтобы UI-тесты **не делали запросов в вашу базу**:

1. `page.addInitScript` подменяет `window.fetch`: URL `http://localhost:3000/...` переписывается на `/__e2e-api/...` **того же origin** до отправки запроса.
2. Vite проксирует `/__e2e-api/*` → `http://127.0.0.1:3104/*` (тестовый бэкенд на копии БД).
3. Так как запрос идёт на тот же origin, CORS-preflight не возникает, а `localhost:3000` не затрагивается вообще.

| --- | --- |
| CoinGecko (напрямую из браузера) | не вызывается: фронтенд ходит только в свой прокси |
| CoinGecko (из бэкенда) | заглушка `test/api/support/fetch-stub.mjs` (подключается через `--import`) |
| Графики `/crypto/chart/*` | в браузере подменяются ответом с **≥3 точками**: бэкенд-заглушка по требованиям этапа 3 отдаёт ровно `days` точек, а для 1 дня это 1 точка и график не рисуется |

| Любой другой внешний хост | запрос **прерывается** — реальная сеть в тестах не используется |

## Принятые решения (там, где был выбор)

Выбраны самые безопасные варианты — вопросов не задавал:

1. **Не останавливал ваши dev-серверы на 3000/5173.** Остановка процесса — действие вне `test/` и может прервать вашу работу с рабочей БД. Вместо этого — свои порты 3104/5174 и проверка их свободы перед запуском.
2. **`window.fetch` переписывается до запроса, а не после ответа.** Так браузер вообще не обращается к `localhost:3000` (ваша база не затрагивается) и не возникает CORS-preflight.
3. **Свой Vite-конфиг** (`test/ui/vite.e2e.config.mjs`) вместо правки корневого: `cacheDir` вынесен в `test/tmp`, поэтому вне `test/` не появляются новые файлы.
4. **Графики подменяются в браузере.** Бэкенд-заглушка по требованиям этапа 3 возвращает `days` точек (для 1 дня — 1 точку), а компонент графика требует ≥2. Менять ожидания API-тестов нельзя, поэтому UI-тесты получают детерминированный ряд с ≥3 точками.
5. **Синтетические картинки.** В заглушке `image` теперь `data:`-URI: браузер не делает запрос к `stub.local`.
6. **Только Chromium.** Другие браузеры не скачивались: цель этапа — UI-логика, а не кроссбраузерность; меньше размер загрузки и времени прогона.
7. **`trace: off`, скриншот только при падении.** Трассы содержат DOM и тела запросов; для отчёта достаточно скриншотов в `test/tmp/04-ui-artifacts`.
8. **Логи сервера фильтруются.** В `04-backend.log` попадает только строка старта, `[schema]` и количество строк с ошибками — без email, SQL и деталей.

## Ограничения этапа

- Только Chromium, десктопный viewport 1280×800; мобильной вёрстки и кроссбраузерности в этом этапе нет.
- Нет визуальных регрессий (скриншот-сравнений) и измерения производительности.
- Внешние API не верифицируются «как есть» — они заменены заглушками (по правилам этапа).
- Тесты последовательные (`workers: 1`), потому что делят один бэкенд и одну копию БД; полный прогон — около 1.3 минуты.
- Проверка изоляции сравнивает количества строк, а не содержимое; тесты работают только со своими аккаунтами `@vitest.local`.
